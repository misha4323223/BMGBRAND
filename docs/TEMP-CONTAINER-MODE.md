# Временный режим «сайт на адресе контейнера»

> Аварийный режим на время, пока домен `booomerangs.ru` не отвечает (недоступен фронт
> API Gateway в Yandex Cloud), а сам контейнер работает и доступен по публичному адресу.
> Позволяет людям войти в личный кабинет и оплачивать заказы **на адресе контейнера**.

## Как это включается

Одна переменная окружения — `TEMP_PUBLIC_ORIGIN`:

```
TEMP_PUBLIC_ORIGIN=https://bba6fol2jvub7mr2uahi.containers.yandexcloud.net
```

- **Прод:** добавить секрет `TEMP_PUBLIC_ORIGIN` в GitHub → Actions secrets
  (`.github/workflows/deploy.yml` уже прокидывает его в ревизию контейнера) и задеплоить.
  Либо задать его в env ревизии контейнера вручную.
- **Локально/превью:** `TEMP_PUBLIC_ORIGIN` в `.env.local` + перезапуск превью.

**Ничего не задано (или пусто) — режим выключен, поведение байт-в-байт как до этой правки.**

## Как вернуть всё обратно

Удалить секрет `TEMP_PUBLIC_ORIGIN` (или очистить переменную) и задеплоить.
Код откатывать не нужно — все ветки режима выключаются сами.

## Что меняется, когда режим включён

| Что | Было | Стало |
|---|---|---|
| Cookie авторизации | всегда `Domain=.booomerangs.ru` | на чужих хостах — без `Domain` (иначе браузер отбрасывает cookie и вход не держится); на `*.booomerangs.ru` — как раньше |
| Возврат с оплаты (`SuccessURL`/`FailURL`) | `APP_DOMAIN` | адрес контейнера |
| Вебхук (`NotificationURL`) | `booomerangs.ru/api/webhooks/tbank` | адрес контейнера (T-Bank его достучится) |
| Ссылки в письмах (подтверждение, сброс пароля, «личный кабинет», статус заказа) | `config.app.domain` / хардкод `www.booomerangs.ru` | адрес контейнера — подмена делается одной точкой в `sendEmail` (см. `rewriteSiteLinks`) |
| Вход через Яндекс ИД | `www.booomerangs.ru/api/auth/yandex/callback` | адрес контейнера (**плюс** адрес надо добавить в приложение Яндекс OAuth, иначе Яндекс откажет) |
| Вебхук Telegram-бота | `APP_DOMAIN`/`SITE_URL` | адрес контейнера |
| Ссылки в сообщениях ВК | `SITE_URL`/`APP_DOMAIN` | адрес контейнера |
| CORS | фиксированный список | + временный адрес из `TEMP_PUBLIC_ORIGIN` |

Точки в коде:

- `server/public-origin.ts` — вся логика режима (`tempPublicOrigin`, `publicBaseUrl`,
  `emailBaseUrl`, `cookieDomainForHost`, `yandexRedirectUri`).
- `server/auth-routes.ts` — cookie входа/выхода, письма подтверждения/сброса, `redirect_uri` Яндекса.
- `server/routes.ts` — возвраты оплаты (заказы, предзаказы, дозаказы, сертификаты), вебхук Telegram,
  ссылка в письме «товар снова в наличии».
- `server/addon-order.ts`, `server/email.ts`, `server/vk-callback.ts`, `server/index.ts`.

## Что режим НЕ меняет (остаётся на домене)

- SEO: `sitemap.xml`, `sitemap_index.xml`, `llms.txt`, `canonical`/JSON-LD (`server/bot-ssr.ts`,
  `client/src/components/SEO.tsx` — константа `CANONICAL_ORIGIN`), фиды для Яндекс.Товаров/ВК
  (они и так берут хост запроса).
- Настройки внешних кабинетов: `redirect_uri` в приложении Яндекс ID, адреса витрин/вебхуков,
  которые вы прописывали вручную у провайдеров.

## Проверка после включения

1. `https://<адрес контейнера>/healthz` → `status: ok`, `ydb.ok: true`.
2. Вход: `POST /api/auth/login` с рабочей парой → `200` и в ответе `set-cookie: auth_token=...`
   **без** `Domain=`.
3. Оплата: сделать тестовый заказ → в логах контейнера строка `[T-Bank] Init request` —
   в ней `SuccessURL`, `FailURL`, `NotificationURL` должны быть на адресе контейнера.
4. После оплаты заказ должен стать `paid` (вебхук либо опрос `GetState` на странице `/order-success/:id`).

## Ограничения

- Адрес контейнера небрендовый и виден в строке браузера.
- Уже отправленные письма и внешние ссылки (реклама, соцсети, закладки) остаются на домене.
- Пока домен не отвечает, «редирект с домена на контейнер» невозможен: на домене некому
  отдать 301 — помочь может только смена DNS на прокси-сервер с сертификатом
  (см. обсуждение в переписке: nginx + Let's Encrypt, DNS у Beget).

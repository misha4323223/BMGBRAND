## Этап 1. Транспорт, авторизация и клиент

### Сделано полностью

- Добавлен HTTP-клиент `OzonHttpClient` для `api-delivery.ozon.ru`:
  - POST с JSON;
  - таймаут 10 секунд;
  - две попытки при сетевой ошибке, `429` и `5xx`;
  - обработка redirect `301/302/303/307/308`;
  - сохранение cookies между redirect;
  - запрет передачи `Authorization` и `Idempotency-Key` на не-Ozon host;
  - извлечение `x-o3-trace-id`.
- Добавлен token-сервис `OzonDeliveryTokenService`:
  - `POST https://xapi.ozon.ru/oauth/token`;
  - grant `client_credentials`;
  - 8 прав по умолчанию: 5 обязательных и 3 опциональных;
  - fallback на обязательные права при `invalid_scope`;
  - поддержка `expires_in` как абсолютного времени в секундах/миллисекундах и как длительности;
  - single-flight: параллельные запросы не плодят запросы токена;
  - статус с маскированным Client ID, сроком и списком прав; токен и секрет наружу не отдаются.
- Добавлен клиент `OzonDeliveryApiClient`:
  - Bearer-токен;
  - при `401` — принудительное обновление токена и один повтор запроса;
  - ошибки API с кодом, сообщением, HTTP-статусом и trace id.
- Добавлена проверка подключения:
  - получение токена;
  - запрос первой страницы `/v1/delivery-point/list`;
  - отдельный статус токена и API.
- Новые env-переменные:
  - `OZON_DELIVERY_API_CLIENT_ID`;
  - `OZON_DELIVERY_API_CLIENT_SECRET`;
  - `OZON_DELIVERY_API_SCOPES` — опционально.
- Старые `OZON_CLIENT_ID` / `OZON_CLIENT_SECRET` в новом контуре не используются; `seller-api.*` scopes отбрасываются.

## Этап 2. Персистентность токена в YDB

### Сделано полностью

- Токен сохраняется в существующую таблицу `bonus_settings` под ключом `ozon_delivery_api_token`.
- Access token шифруется AES-256-GCM; ключ выводится из `JWT_SECRET`.
- В YDB хранятся:
  - зашифрованный access token;
  - срок действия;
  - время получения;
  - scopes;
  - SHA-256 отпечаток Client ID.
- Сырые Client ID, Client Secret и открытый access token в БД не пишутся.
- При старте сервера вызывается `restoreFromStorage()`:
  - валидный токен подхватывается без нового запроса к Ozon;
  - токен другого Client ID игнорируется и стирается;
  - истёкший токен стирается;
  - повреждённый JSON/шифротекст игнорируется;
  - ошибка YDB не блокирует старт и не мешает получить новый токен.
- При смене `JWT_SECRET` старый токен не расшифруется и будет заменён новым.

### Что проверено

В составе 27 тестов API:

- второй экземпляр сервиса берёт токен из хранилища без сети;
- в YDB сохраняется отпечаток Client ID, а не сам Client ID/Secret;
- сбой YDB не мешает получению токена;
- валидный токен читается;
- подменённый шифротекст игнорируется;
- токен другого Client ID игнорируется и стирается;
- истёкший токен игнорируется;
- повреждённый JSON игнорируется.

### Статус

- ✅ Реализация завершена.
- 🧪 Mock-хранилище и сценарии рестарта проверены.
- 🟡 Живая YDB не проверялась.
- 🟡 Не проверено реальное поведение после рестарта контейнера и при параллельной записи.

### Осталось

  - телефоном;
  - объявленной стоимостью;
  - габаритами;
  - `cutoff_at`;
  - `shipment_method_id`.
- Если quote не прошёл, `/v1/order/create` не вызывается.
- Создаётся одно отправление; API допускает до 100, но текущий чекаут всегда одна посылка.
- Поддержаны `order_external_id`, `posting_external_id`, ФИО получателя.
- `Idempotency-Key`:
  - генерируется сервером, если не передан;

  - network error;
  - `5xx`;
  - неразборчивый `200`;

- Разбираются `order_number`, `order_external_id`, `postings`, `posting_number`, `request_id`, `posting_external_id`, срок и `cutoff_at`.
- Добавлен админский endpoint `POST /api/admin/ozon-delivery-api/order/create`.
- Сервер требует `confirm: true`; UI требует отдельный чекбокс подтверждения.
- `adminFetch` теперь сохраняет HTTP-статус и тело ошибки, чтобы форма получала `mayHaveBeenCreated`, `traceId` и `idempotencyKey`.
- В админке появился блок «Создание заказа» с предупреждением, результатом и ошибками.

### Важное ограничение Ozon

Ozon Delivery ожидает телефон получателя, зарегистрированный в Ozon. Если телефон не зарегистрирован, `/v1/order/create` не создаст заказ. Для проверки используйте такой номер.

### Как проверить после деплоя

1. Откройте админку → Интеграции → **Ozon Delivery API**.
2. Нажмите «Проверить подключение»: токен должен быть получен, API — доступен.
3. Нажмите «Синхронизировать ПВЗ» и дождитесь статуса «Готов» (это долго: около 900 страниц).
4. Проверьте, что в чекауте для тестового города появляются ПВЗ Ozon.
5. Включите переключатель «Показывать Ozon в чекауте».
6. Оформите тестовый заказ: товар, ПВЗ, телефон, **зарегистрированный в Ozon**. Стоимость доставки должна прийти из Ozon, а не равняться фиксированным 350 ₽.
7. Оплатите заказ и проверьте его в кабинете Ozon Доставки.
8. Если создание не удалось, не меняйте `Idempotency-Key`: проверьте `addon_data` заказа (`ozonCreateFailed`, `ozonCreateUnknown`) и при необходимости повторите через админский retry.

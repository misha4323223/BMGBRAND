# Проблемы синхронизации 1С с Yandex Serverless

## Контекст
BMG E-commerce store использует Yandex Serverless Containers для приёма данных из 1С ERP (CommerceML).
При импорте товаров часть изображений не сохраняется в Object Storage.

---

## РЕШЕНИЕ (Октябрь 2026): лимит контейнера и фрагменты 1С

«Нормальные или битые» файлы — это лимит Yandex Serverless Containers:
**3.5 МБ на HTTP-запрос, включая заголовки** (в Replit лимита не было, поэтому там
проходили файлы любого размера). Сайт сам говорил 1С `file_limit=104857600`, поэтому
большое фото приходило ОДНИМ запросом и обрезалось шлюзом.

Что сделано:
- `mode=init` теперь отдаёт `file_limit=2097152` (2 МиБ) — 1С сама делит большие
  файлы на части (официальный протокол: «если понадобится передать файл большего
  размера, его следует разделить на фрагменты»). Части идут одним и тем же
  `POST mode=file&filename=...`, номера части нет — сайт их склеивает.
- Склейка: `server/lib/one-c-file-parts.ts` (части в Object Storage,
  `1c_parts/<type>/<filename>/`). Готовый файл публикуется сразу, как только 1С
  перешла к следующему файлу или к `mode=import` (`flushPendingOneCFiles` в
  `server/routes.ts`); полный обход бакета — не чаще раза в минуту и без свежих
  сборок (свежее 20 с — их может дописывать другой экземпляр контейнера).
  Перед публикацией файл проверяется на целостность: обрезок (обмен оборвался)
  не публикуется и не подмешивается к повторной выгрузке.
- `mode=import` использует склеенный XML, а не тело запроса (тело тоже режется шлюзом).

Проверка логики склейки: `server/__tests__/one-c-file-parts.test.ts` (vitest, гоняется в CI).

Осталось отдельной задачей: выгрузка заказов на сайт (`mode=query`) ограничена лимитом
ОТВЕТА контейнера (3.5 МБ) — это не связано с картинками.

### Причина проблемы: Настройки контейнера

Были настройки:

| Параметр | Было | Проблема |
|----------|------|----------|
| Подготовленных экземпляров | **0** | Холодный старт 5-15 сек |
| Экземпляров в зоне | **0** | Контейнеры не готовы |
| Одновременных вызовов | **4** | Маловато для параллельной загрузки |

#### Что происходило:
1. 1С начинает отправлять файлы
2. Yandex Cloud поднимает контейнер (cold start: 5-15 секунд)
3. Пока контейнер поднимается — запросы накапливаются
4. Часть запросов отклоняется (429) или таймаутится
5. Файлы теряются

### Рекомендуемые настройки:

| Параметр | Рекомендация |
|----------|--------------|
| Таймаут | 2 минуты ✅ |
| Одновременных вызовов на экземпляр | **16** |
| Подготовленных экземпляров | **1** |
| Экземпляров в зоне | **1** |
| Одновременных вызовов в зоне | **0** (без ограничений) |

**Стоимость:** Немного выше, но гарантирует стабильную работу.

## Разница: Replit vs Yandex Serverless

| Аспект | Replit | Yandex Serverless |
|--------|--------|-------------------|
| **Контейнеры** | 1 постоянный | Много, создаются по требованию |
| **Обработка запросов** | Последовательно | Параллельно, разными инстансами |
| **Память** | Сохраняется | Сбрасывается между запросами |
| **Время жизни** | Постоянно работает | Уничтожается после простоя |
| **Cold start** | Нет | Да (при 0 prepared instances) |

### В Replit:
```
1С → файл 1 → [Контейнер] → S3 ✅
1С → файл 2 → [Контейнер] → S3 ✅  (тот же контейнер)
1С → файл 3 → [Контейнер] → S3 ✅  (тот же контейнер)
```

### В Yandex Serverless (при старых настройках):
```
1С → файл 1 → [Контейнер A] → S3 ✅
1С → файл 2 → [Контейнер B] → очередь переполнена → 429 ❌
1С → файл 3 → [Контейнер A] → S3 ✅
1С → файл 4 → [Контейнер C] → таймаут → ❌
```

## Другие потенциальные проблемы (на будущее)

### Проблема: S3 Eventual Consistency

```
10:44:30.100 - POST image.jpg → S3 PUT (успех)
10:44:30.200 - GET import → S3 LIST → image.jpg НЕ ВИДЕН ещё
10:44:31.000 - S3 LIST → image.jpg теперь ВИДЕН
```

Yandex Object Storage (как и AWS S3) имеет **eventual consistency**.
После PUT объект может быть **не сразу виден** при LIST операции.
Задержка: от 100мс до нескольких секунд.

### Проблема: Rate Limiting на Object Storage

Лимиты S3:
- ~3500 PUT операций/секунду на один prefix (папку)
- При превышении → throttling

### Проблема: Порядок CommerceML протокола

1С может вызвать import ДО завершения загрузки всех файлов:
```
POST image1.jpg ✓
POST image2.jpg ✓  
POST import.xml ✓
GET import ← обработка начинается ЗДЕСЬ
POST image3.jpg ← ещё не отправлен!
```

## Как диагностировать

### 1. Проверить логи контейнера:
- Yandex Console → Serverless Containers → Logs
- Искать: 429, 503, timeout ошибки

### 2. Проверить настройки контейнера:
- Лимит concurrent requests
- Prepared instances
- Таймаут выполнения

### 3. Проверить Object Storage:
- Yandex Console → Object Storage → Monitoring
- Искать: throttling, 5xx ошибки

### 4. Тест через Replit:
- Подключить Replit к production YDB/S3
- Запустить выгрузку из 1С на Replit
- Если работает — проблема в настройках контейнера

## Альтернативные решения

### Вариант A: Использовать VM вместо Serverless
Постоянный сервер без холодных стартов.
**Минус:** Выше стоимость.

### Вариант B: Синхронизация через Replit
Использовать Replit как постоянный прокси для 1С.
**Минус:** Зависимость от стороннего сервиса.

### Вариант C: Ленивая загрузка картинок
Не проверять наличие в S3, генерировать URL напрямую.
**Минус:** Если файл не загружен — битая картинка.
